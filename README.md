# 银铃

> 基于多源弱信号的社区老年人异常识别与分层核验机制

**当前阶段**：系统搭建（完整版 27 页；运营向功能标「暂缓」，详见 `docs/02-系统端功能规格.md` 0.1 节）

---

## 这是什么

一套给社区用的老人异常发现与核验系统。不新增硬件，复用已有信号（小程序打卡、四键求助、社区服务记录、家属确认），把弱信号合成为「偏离度 D × 置信度 Q」，再按关系亲疏把核验任务派给家属、志愿者、社区工作者。

**核心不是算法，是分流**：让人力只投在高偏离 + 高置信的那一格。

## 本地跑起来

### 1. 装环境

| 工具 | 版本 | 用途 |
|---|---|---|
| Node.js | 20+ | 前后端 |
| MySQL | 8.0+ | 数据库 |
| 微信开发者工具 | 最新 | 小程序 |

### 2. 建库

```bash
mysql -u root -p < sql/schema.sql
mysql -u root -p yinling < sql/seed.sql
```

### 3. 启动后端

```bash
cd server
npm install
cp .env.example .env      # 填数据库密码
npm run dev               # 默认 http://localhost:3000
```

### 4. 启动管理端

```bash
cd web
npm install
npm run dev               # 默认 http://localhost:5173
```

### 5. 小程序

用微信开发者工具打开 `miniprogram/`，把 `app.js` 里的 `baseUrl` 指向本机后端。

## 协作流程

**`main` 受保护，不能直接 push。** 所有改动走 PR，且需要至少 1 人 approve。

```
git checkout -b feat/agent-order      # 开短分支
# 写代码
git commit -m "feat: 承办人工作台骨架"
git push -u origin feat/agent-order   # 推上去
# 在 GitHub 开 PR，等 review
```

- 分支命名：`feat/xxx`、`fix/xxx`、`docs/xxx`
- 提交信息：`feat: xxx` / `fix: xxx` / `docs: xxx`
- **合并前本地必须跑通**，main 要随时能跑
- 有接口/表结构变更，同一个 PR 里把 `docs/` 对应的那份一起改

## 三条不能破的约束

1. **原始录音一律留存**，撤回只撤单、不删音频
2. **AI 不独立决定不上门**，判定权在人手上
3. **处置结论必填**，它是台账和指标的唯一数据源
