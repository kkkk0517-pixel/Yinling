# #12 调度接入：已确认设计

2026-11-05，用户明确回复“按此方案实现”，批准：默认服务启动补跑本周期一次；T2 立即且独立、失败 30 秒退避；M1 可选 jobs 和 T2 最近成功时间；audit_log 留档；开发 D3 单点连续倍速；自动调度运行时 D1 拒绝清库；接口扩展仅本地草案待 B/PM 评审。

- 原生定时器，无新依赖/表结构。UTC+8；T1 读取现有 day_cut_hour，T2 默认每30秒，T3 默认03:00，T4 默认每60分钟。其他频率由启动配置设置。
- 启动先尝试 T2；日批按 T1→T3→T4 排序，T4 完成后消费 L4。T1 未完成或失败不放行相关 T4；T3 失败不妨碍会独立复算基线的 T4。只处理最新周期，不追放全部漏掉的 tick。
- 同任务覆盖业务执行及健康完成记录的完整互斥；T2 与日批调度分离。使用独立数据库会话的调度器所有权锁，避免误启两份托管循环，不占用业务连接池。
- 失败用安全错误码记录，禁止原始异常消息、SQL、凭据和个人输入进入调度日志。数据库健康留档失败不冒充成功；内存状态/日志仍保留错误。
- 健康使用真实时间记录执行/失败；业务周期及 SLA 使用唯一业务 now()。T2 超过两分钟未成功、最近尝试失败或健康持久化失败，不能标为健康。停止/未启动不假装正在执行。
- audit_log 记录任务开始/成功/失败及快照。重启可读取历史，当前是否运行以本实例实际状态为准，不把旧 running 记录当作当前成功。
- 单点业务时钟支持1/10/60，切换连续且不回退；变更基准留现有审计表，进程重启可继续。生产环境拒绝非1倍速；M8 不得绕过 D3 约束。
- M1 可选 jobs、lastJobAt=T2 最近成功；保留公共 health 的数据库探针原语义，避免把数据库连通当作调度器健康。
- 自动任务运行期间拒绝 D1；停用调度并重启后才可重置。维护锁阻止另一托管进程在清库中启动。重置只作用于当前配置的数据库，完成后复位业务时钟/任务健康；不实现 #25 的其他演示增强。
- app 导入不启动循环。服务入口负责启动与停止：先取消调度、等待在途任务和 HTTP 完成，随后关业务池/所有权连接。硬杀、真实触达、实际上门及线上效果不据本地测试推断。
- 独立 CLI 原任务体仍可直接调试；不把手动脚本当作自动循环正常的证据，也不声明跨任意非托管写入的全局恰好一次保证。
