# #9 L2 个体基线：已确认设计

2026-11-05，用户明确回复“按此方案实现”，确认下列计算规则。依据：Issue #9、功能规格 §6.2、接口列表 T3。规则是本项目实现选择，不构成风险阈值或效果验证。

- 使用 UTC+8 及现有 `day_cut_hour`，取运行时所在统计日之前最近 14 个完整统计日；当前未结束的统计日不参与。T3 在 03:00 运行时，04:00 尚未结束的当天不会提前入样。
- 指标：`calendar_confirmed`、`app_opens`、`request_count`。每项计算原始中位数和原始 MAD，即绝对偏差的中位数，不乘正态分布缩放系数。
- 必须覆盖窗口中 14 个不同日期；缺日不补零。存在的零值参与计算。无有效信号历史也输出“信息不足”。有效信号历史指窗口内至少存在一次上述非零活动，或窗口内发生的打开/服务/成功回执时间；仅携带窗口之前的旧接触时间不算。
- 空数据、缺日、重复日或非法指标不能产生“正常”或数值 D；返回 `status=insufficient`、`message=信息不足`，D 为 `null`。
- 对就绪基线及完整合法的当前指标，分项 `D = δ / (δ + max(MAD, 1))`，其中 `δ = |当前值 - 中位数|`；总 D 为三个分项最大值。MAD 为零仍可计算；不输出异常判断，不接入 Q、阈值或预警。
- 基线快照包含版本、老人 ID、统计日期、计算时间、窗口、完整输入记录 ID/日期/值、缺失/非法日期、状态和中位数/MAD。写入现有 `audit_log`，`action=baseline_calculated`、`target=elder`，并缓存最近一批结果。
- 同一批的读取与审计写入在事务内完成；提交成功后才整体发布缓存。重算追加审计快照，不覆盖旧版本；历史从数据库读取，进程重启后仍能查询。缓存返回副本。
- 只处理当前社区中 active 且 monitor 的老人。固定 14 天；配置不为 14 或切日时刻非法时显式失败，不静默换算法。
- 提供 T3 任务体和 CLI；自动调度属于 #12。沿用当前工作副本，保留 #8；不做 Git 写入、不改表结构、不增依赖、不改 HTTP 契约。
