# #11 L4 路由：已确认设计

2026-11-05，用户明确确认三组规则：当前层主责控制路由；配置层和承办/管理员兜底；授权沿用现有表、新增可选提示字段和独立补证据回执接口，并同步本地 docs/04 供团队评审。

## 路由和计时

- 消费 #10 的 strong/insufficient。strong 建普通核验单，按配置的 1–4 层前进；层中启用成员同步通知，只有唯一有效主责才使该层可用。缺主责、多主责或主责不可用的层跳过并留痕，不自行提拔知会。
- 配置链中尚无承办人时，追加本社区启用承办人，缺省按 person.id 选首位；最后追加管理员兜底。配置的管理员可作为终点，兜底阶段不是新增可编辑关系层。没有启用承办/管理员时仍保留未完成工单和配置待办，不伪称已通知或已处置。
- 第 1 层默认 15 分钟，其余默认 120 分钟；取 layerN_wait_min，非法值显式失败。仅实现 relation 模式；distance 模式不静默回退，不实现暂缓的扩圈或值班表。
- 普通单同一 alert 唯一键幂等；30 秒内同老人同类未完成单可合并，不覆盖原 alert_id、不重置 SLA，新依据写事件关联。紧急单不同 clientRequestId 不合并，同一 ID 仍幂等。
- 只有当前激活层的主责成功回执才停计时，工单保持待承办确认；主责 unreachable 立即 CAS 升级。知会只留证据。旧层迟到、重复及已结单回执不能改变当前路由。
- 当前通知归属以派发事件的层级和通知 ID 快照为准，不使用可能已被 M6 修改的实时 relation.level 来判断旧通知。
- CAS 包含 id、观察到的 current_layer、状态和原 deadline；超时还要求 deadline 到期。CAS 失败不写升级事件、不通知新层。状态、通知和事件在同一事务内保存。
- H3/H4 在服务端核验实际承办人及启用状态；回执不等于关单。终局结论依靠 disposition.uk_order 唯一键；升级、补上门不是终局结论，不占用该唯一行。

## 紧急单

- E6 跳过 L3 和逐级等待，全链关系人、承办人、管理员同时收到站内可见信息。关系人的通知写 notification；不为非关系人伪造 relation_id，承办/管理员通过现有工作台及可选提示字段看到指令。
- 初始 SLA 为 5 分钟（沿用现有 E6）；没有承办人直接交管理员。指令要求打电话和出发并行；系统只记录指令，不伪造 call/visit 人类动作。关系人回执不能取消紧急处理要求。
- H3 电话动作不免除上门；出发/上门动作进入承办跟进，按承办 SLA 留跟进截止。H4 电话确认未上门时保留开放单和当日上门待办，自然日午夜 UTC+8 截止，不写最终 disposition。到期交管理员。
- 紧急单不能用电话方式关单，真人提交上门结果才能形成最终结论。电话确认可按规范降级跟进，但不得丢掉上门义务；实现用事件及 deadline 保留义务。

## 补证据和接口

- insufficient 不建核验单：audit_log 保存请求及接收人快照，R1 可选 evidenceRequests 显示“今天还没联系上，您方便看一眼吗”。
- 新增 R10 `POST /relation/evidence-requests/:id/ack`，body 为 clientRequestId(UUID v4)、result(ok_called/ok_visited/unreachable)。仅当前关联且收到请求的启用关系人可调；唯一键写 signal_event，重复 ID 返回已有结果，跨主体复用拒绝。
- 成功回执形成 family_confirmed 信号，联系不上仅记录 family_unreachable 并形成管理员待办，不自动升格或造核验单。成功证据可供下一轮 L1/L3 使用；不能关闭既有核验单。
- R1 新增可选 evidenceRequests，H2 新增可选 routing（并行动作/上门义务等），M1 新增可选 routingTodos。保留原字段、权限和返回包络；同步 docs/04。本地无开放 PR 涉及该共享契约，尚未取得远程评审或 A/B 界面验证。
