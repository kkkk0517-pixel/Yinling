## 二、五个关键页面

### R-02 今日卡片（关系人端最重要的一页）

```
┌──────────────────────────────┐
│ 张桂芳 · 今天还没消息          │
│ ──────────────────────────── │
│ 昨天没撕日历，今天也没打开过。  │
│ 上次有人去看她：10 月 21 日，王姨 │
│                              │
│ ┌──────────────────────────┐ │
│ │  我去看过了，没事          │ │
│ ├──────────────────────────┤ │
│ │  打过电话，没事            │ │
│ ├──────────────────────────┤ │
│ │  联系不上，请社区去看看     │ │
│ └──────────────────────────┘ │
│                              │
│ 还有一件事：她想买米和酱油      │
│ [ 我去办 ]                    │
└──────────────────────────────┘
```

**硬要求：**
- 标题**不出现**"预警/异常/风险"，用"今天还没消息"
- 触发原因必须写成**人话**（"昨天没撕日历"），不能写"连续 2 天 calendar_confirmed=false"
- 三个按钮的点击区域 ≥ 56px 高
- 主责看到的是这三个按钮；知会看到的是同一页，但按钮下多一行"你是知情，主责是李敏"

### H-02 核验单详情（承办人）

见功能规格 3.3 的卡片。补充三条页面级规则：

| 项 | 规则 |
|---|---|
| 首屏 | 老人姓名 + 触发原因 + SLA 倒计时 + 三个动作按钮，**一屏内不滚动** |
| 信号来源 | 默认折叠成一行"依据 3 条信号"，点开才展开 |
| 通知记录 | 必须显示"谁、几点、读没读、回没回"——这是"为什么轮到我"的解释 |

### H-03 处置结论（决定数据质量的一页）

```
方式： [电话] [上门]        ← 点上面动作时自动选中
结论： [没事] [有事已处理] [联系不上转社区] [老人说不用管]
备注： ______________________  （选填，≤50 字）
```

- **耗时自动算**，不让填
- 提交后 **1.5 秒**回到工作台，不弹二次确认
- 紧急单：第一个按钮变成「已上门确认，没事」，另加「电话确认，未上门」

### M-04 关系链编辑器（核验路由的核心页）

```
第 1 层  [责任组] 李敏（主责）· 李强 · 李娟    [+ 加人]
         王姨（结对志愿者·知会）              [+ 加人]
         等待 [15] 分钟
第 2 层  陈师傅（承办人）                      [+ 加人]
         等待 [120] 分钟
第 3 层  社区值班                              [+ 加人]
                                     [+ 加一层]
```

- 主责用**实心标记**，知会用空心，一眼能分
- 拖拽排序，但**不允许多层之间拖**（层是语义，不是顺序）
- 改完必须点"保存并生效"，不自动保存（改错会直接影响升级）

### M-10 未读超时清单（v1 唯一的兜底）

```
超时未读（3）
┌────────────────────────────────────────────┐
│ 张桂芳 · 女儿李敏 · 已等 22 分钟  [拨号]     │
│ 王建国 · 儿子王强 · 已等 41 分钟  [拨号] ⚠  │
│ 刘秀英 · 无家属   · 已等 8 分钟   [指派]     │
└────────────────────────────────────────────┘
```

- 按等待时长降序，超过 30 分钟标红
- **一键拨号**（tel: 链接），不跳转其他 App
- 拨完可以勾"已电话催办"，留痕
- 这页是 v1 兑现"30 分钟"的唯一手段，**不能砍**

## 四、现在还缺什么

### 4.1 会直接卡住开发（不定就写不下去）

| # | 缺什么 | 为什么卡 | 谁来定 |
|---|---|---|---|
| 1 | **账号与绑定流程** | 老人怎么进系统？家属怎么挂到老人身上？邀请码谁生成、有效期多久、一个老人最多绑几个？不定这个，P-01/P-02 写不了 | 你拍板 |
| 2 | **录音存哪、存多久** | 报告承诺"永久留存"，但"永久"要落成具体策略：存储位置、保留期、谁能播、撤回后删不删 | 你拍板 |
| 3 | **台账导出的字段清单** | 报告六（二）说"字段与口径一致"，但没列具体列名。不定这个，M-11 导出就是废的 | 你拍板 |
| 4 | **一位家属对应多位老人怎么办** | 一个女儿同时是爸妈两位老人的主责人，一次触发收两条通知会烦。要合并成一条还是分开 | 我建议合并，你确认 |

### 4.2 会影响真用起来（上线前必须定）

| # | 缺什么 | 不解决的后果 |
|---|---|---|
| 5 | **服务单的钱** | 代购垫付谁出、怎么记、怎么报。不解决，没人敢接代购单 |
| 6 | **夜间与节假日值班** | 凌晨 2 点触发，第 3 层"社区值班"是谁？现在的 30 分钟承诺在夜里是空的——这是**研究中也尚未解决的问题**，需要在设计中明确 |
| 7 | **地址怎么变成坐标** | 距离派单要经纬度，农村没有门牌号。要么手工在地图上点，要么放弃距离派单 |
| 8 | **老人退出 / 身故** | 账号怎么停、关系链怎么解、数据留多久。真实运营一定遇到 |
| 9 | **老人端的服务单进度** | 老人端 P5 是"二期可选"，但服务单做完没有进度查询，老人会重复按同一个键 |

## 五、一个提醒：v1 的页面量偏大

按上表，v1 要做 **24 个页面**。5 人团队、2 个月，还要写后端和联调——这个量会拖。

**建议按这个顺序砍：**

| 砍什么 | 怎么砍 | 省下 |
|---|---|---|
| R-05 / H-06 我的记录 | 合并成各自首页的一个"历史"tab，不单独成页 | 2 页 |
| M-12 审计日志 | 推到 v1.5（但表要先建，日志先写） | 1 页 |
| M-01 总览 | v1 只做 4 个数字，不做图表 | 半个页面 |
| M-08 工单列表 | 和 M-11 导出合并成一页（筛选 + 导出按钮） | 1 页 |
| M-13 真异常录入 | 已推二期 | — |

砍完 v1 ≈ **18 页**，仍然是紧的，但能交付。

**如果还要再砍，最后砍的是**：M-05 批量导入（改成逐个建，慢但能用）、R-03 近况简报（先只显示"最近一次服务"一行）。
**绝对不能砍的**：R-02、H-02、H-03、M-04、M-10、M-11。这六个是机制能不能被看见、指标能不能长出来的全部。
