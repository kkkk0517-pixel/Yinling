## 零、通用约定

| 项 | 约定 |
|---|---|
| Base | `/api` |
| 鉴权 | `Authorization: Bearer <token>`，登录后签发，7 天有效 |
| 返回 | `{ "code": 0, "data": {...}, "msg": "" }`；`code != 0` 为错误 |
| 分页 | `?page=1&size=20` → `data: { list: [], total: 0 }` |
| 时间 | `YYYY-MM-DD HH:mm:ss`（服务器本地时区，UTC+8） |
| **幂等** | 所有"创建类"写接口必带 `clientRequestId`（UUID v4），重复提交返回已有对象 |
| 错误码 | 401 未登录｜403 无权限｜404 不存在｜409 状态冲突｜422 参数错｜500 服务端 |

**权限前缀：**

| 前缀 | 谁能调 |
|---|---|
| `/auth` | 所有人（登录前） |
| `/elder` | 居民 |
| `/relation` | 关系人 / 服务承接人 |
| `/agent` | 承办人 |
| `/admin` | 管理员 |
| `/demo` | 管理员（演示用） |

**R1 新增可选字段**：`evidenceRequests?: [{ alertId, elderId, elderName, message, requestedAt }]`。仅返回当前关联且曾收到请求的启用关系人的待处理提示；已有成功证据后不继续催家属。A 必须对字段缺省做兼容，不应把它当作 `notification.id`。

**R10 幂等及权限**：UUID v4 必填，重试复用原 ID，唯一键写 `signal_event`；跨主体/用途复用返回 409。新的观察使用新 UUID 追加留档，不覆盖之前的回执。成功记录 `family_confirmed`；联系不上记录 `family_unreachable` 并交管理员跟进，不自动提高置信度或创建核验单。后来的成功只解决更早的待办，不能隐藏更新的“联系不上”反馈。

**R3 路由规则**：只有当前派发快照中的主责成功回执才停 SLA；主责联系不上立即 CAS 升级。知会、旧层迟到、重复和已结束单回执只留证据，不修改当前路由。紧急单关系人回执不能取消承办/上门义务。

## 四、处置端（10）

| # | 方法 路径 | 入参 | 出参 | 页面 | 备注 |
|---|---|---|---|---|---|
| H1 | `GET /agent/workbench` | — | `{ mine[], pool[], elders[], overdueCount }` | H-01 | `overdueCount` 替代未读清单页 |
| H2 | `GET /agent/verify-orders/:id` | — | `{ elder, alert, signals[], notifyLog[], slaLeft, actions[], routing? }` | H-02 | `signals` 按本单 alert_id 绑定；只读查看者/已结束单无执行按钮 |
| H3 | `POST /agent/verify-orders/:id/action` | `action: call\|visit\|escalate` | `{ ok, methodAutoFilled }` | H-02 | 记 `order_event`，用于算耗时 |
| H4 | `POST /agent/verify-orders/:id/disposition` | `resultCode, method, note?` | `{ ok, orderId }` | H-03 | 唯一约束，重复提交返回已有 |
| H5 | `POST /agent/verify-orders/:id/transfer` | `toPersonId, reason` | `{ ok }` | H-02 | 拒单/转单必填原因 |
| H6 | `GET /agent/service-orders` | `lat?, lng?` | `{ list[] }` | H-01 待接 | 按片区/距离排序 |
| H7 | `POST /agent/service-orders/:id/accept` | — | `{ ok }` | H-04 | |
| H8 | `POST /agent/service-orders/:id/start` | — | `{ ok }` | H-04 | 记"出发" |
| H9 | `POST /agent/service-orders/:id/complete` | `content, amount?, durationMin?` | `{ ok, billId? }` | H-04 | 有金额则自动生成账单 |
| H10 | `GET /agent/elders/:id` | — | `{ elder, chain[], history[] }` | H-02 折叠 | 只读 |

> **H3 必须先调再调 H4**。耗时 = H3 时间戳到 H4 时间戳，前端不能传。

**H2 新增可选字段**：`routing?: { phaseLabel, requiredActions[], parallel, completedActions[], needsVisit, visitDueAt, canAct }`。紧急单要求电话/出发并行；completedActions 只来自真实提交的人工动作，不由系统指令填充。普通单仅当前承办人可操作；同社区其他承办人可只读紧急广播，不能据此替代主责关单。

**H3/H4/H5 补充语义**：操作人必须是当前启用承办人。转单不延长原 SLA；后续扫描不得自动撤销人工转单。`unreachable_escalated` 和紧急 `phone_confirmed_not_visited` 是阶段反馈，不写最终 disposition、不关闭原单；B 需刷新 H2 的 status/routing，不能仅据 `ok` 判断已关单。电话确认后的上门义务截止自然日午夜 UTC+8；重试不延长截止，也不撤销已发生的管理员升级。紧急最终结论必须为上门方式。终局 disposition 仍受 order_id 唯一键保护。

**E6/H3 重试**：E6 promise 依据当时实际派发快照生成，零接收人不宣称已通知，后续同 UUID 保留原事实。紧急首次 visit 的跟进截止固定保存，后续相同动作或 SLA 参数变化不延长它；动作记录仍只表示人工提交声明，不表示系统验证了实际上门。

首次出发后才提交“电话确认未上门”时，也不延长已固定的跟进SLA；订单取该截止与午夜中较早值，午夜上门义务另行保留。B需区分H2倒计时与routing.visitDueAt，不能用午夜覆盖更早的升级时点。

E6 已有请求重放先校验当前身份及老人归属，再返回旧单/广播事实；配置后续变坏不影响授权重放，新建仍拒绝非法配置。账号停用或跨老人/跨用途复用不能借幂等绕过权限。

**M1 新增可选字段**：`routingTodos?: [{ id, kind, orderId?, alertId?, elderId, elderName, message, createdAt, dueAt?, needsAction, recipientIds?[] }]`。包括管理员兜底、补证据联系不上、紧急知会/待上门和旧单核对。提示/待办不代表实际已触达或已上门；无启用接收人仍留待办，不伪称发送成功。B 对缺省字段兼容；页面显示尚待 B 集成。

**M1 任务健康（#12，可选，待 B/PM 评审）**：`lastJobAt?: string|null` 为本实例当前观察到的 T2 最近成功时间，不再使用占位值。`jobs?: { version, state, enabled, running, owning, lastErrorCode, businessTime, timeScale, tasks }`；state 为 `not_started / starting / running / standby / disabled / degraded / stopped`。tasks 以 T1–T4 为键，各含 `running, healthy, stale, lastScheduledAt, lastBusinessAt, lastStartedAt, lastSucceededAt, lastFailedAt, lastFinishedAt, attempts, failures, consecutiveFailures, lastErrorCode, lastStoreErrorCode, lastLogErrorCode, blockedOn`；未发生的时间为 null。时间仍用 UTC+8 字符串：计划及 lastBusinessAt 属业务时间，执行/成功/失败时间属真实时间。

B 应对字段缺省兼容；T2 超过 **真实两分钟** 未成功、最近失败、健康留档失败或实例未运行时不得显示健康。备用实例只展示其最近恢复的历史，不冒充另一个进程正在本机执行；总览应连接当前 owner。`GET /api/health` 仍只是数据库连通探针，不能据其 200 判断跑批健康。

**M8 调度参数**：`day_cut_hour` 必须是 0–23 的整数或数字字符串，拒绝空值/布尔/对象，按规范数字字符串保存并更新本实例计划。`time_scale` 复用 D3 的连续切换和生产限制。另一个托管实例持有所有权时，修改切点/倍率返回 409，需在 owner 实例操作。

切点读写及计划发布与启动恢复共享控制锁；接任owner必须重新同步，不能复用取得所有权前的旧时钟。锁冲突返回409，B应允许稍后重试。

## 七、定时任务（非 HTTP，但要有）

| # | 任务 | 频率 | 做什么 |
|---|---|---|---|
| T1 | 切日 | 每天 04:00 | 建当天 `signal_daily` 行；重置"今日已确认" |
| T2 | SLA 扫描 | 每 30 秒 | 扫已到期的单，使用统一业务时间，升一层（CAS 更新） |
| T3 | 基线计算 | 每天 03:00 | 算近 14 天中位数/MAD，写入内存缓存 |
| T4 | 分层扫描 | 每小时 | 对 `monitor_level='monitor'` 的老人算 D/Q，产出 `alert` |

**T2 是唯一不能挂的。** 挂了整个机制就停在那，演示当场穿帮。建议加一个"最近执行时间"字段，管理端总览底部显示，超过 2 分钟没跑就标红。

**#12 运行策略（用户确认）**：默认随服务启动补跑最新周期一次，T2 立即独立执行，日批按 T1→T3→T4；T4 后消费 L4。T1 未完成/失败阻塞相关 T4；坏日批切点不阻止 T2，T3 失败不阻止会独立复算基线的 T4。同任务覆盖执行及完成记录的互斥，不追放全部历史 tick。失败记安全错误码、audit_log 快照，按真实30秒退避重试。数据库留档失败仍有内存错误/日志，不能显示健康。停止先取消定时器并等待在途结束，再释放连接。

T1 切点取 `param.day_cut_hour`；其余启动配置见 `server/.env.example` 的 `JOB_T2_INTERVAL_SEC / JOB_T3_HOUR / JOB_T4_INTERVAL_MIN`。每个数据库只允许一份托管调度持有独立会话所有权，备用实例不执行任务；初始化失锁必须中止。已有手动 CLI 可调试原任务体，不提供跨任意非托管写入或硬杀的全局恰好一次保证。没有新增 HTTP 路由或表结构。

## 八、三个最容易写错的接口

### 8.1 `POST /elder/requests`（四键建单）

```json
// 请求
{
  "keyType": "buy",
  "audioFileId": "https://.../a1b2.webm",
  "clientRequestId": "9f1c...-uuid"
}
// 响应
{
  "code": 0,
  "data": {
    "orderId": 1024,
    "promise": "今天之内有人联系您",
    "canCancelUntil": "2026-10-23 15:58:10"
  }
}
```

**三个坑：**
1. 不带 `audioFileId` 也要能建单（老人按了键但没说话）。**按钮本身就是信息。**
2. `promise` 从 `param` 读时限再拼话术，不能硬编码。
3. 30 秒内同 `elderId + keyType` 有未完成单 → 返回已有单，不新建。

### 8.2 `POST /relation/notifications/:id/ack`（回执）

```json
{ "result": "ok_called" }
```

服务端要做三件事：
1. 写 `notification.ack_at / ack_result`
2. **如果 `is_accountable = 1`** → 清 `verify_order.sla_deadline`（停计时）
3. 写 `order_event(action='ack')`

知会点了第 2 步不做。**这是"只有主责能停计时"的全部实现，别写漏。**

### 8.3 `POST /agent/verify-orders/:id/disposition`（处置结论）

```json
{ "resultCode": "normal", "method": "visit", "note": "老人在家，手机没电" }
```

服务端算的，前端一律不能传：

| 字段 | 怎么算 |
|---|---|
| `duration_min` | 该单第一条 `action` 事件到现在的分钟差 |
| `is_invalid_check` | `normal` 或 `declined` → 1，其余 0 |

**这两个字段决定主指标。让前端传，指标就能被刷。**
